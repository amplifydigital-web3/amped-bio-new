## 1. What ships

| Area                 | Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `access.rules.stats` | A private query with range `7d`, `30d` or `90d`. It returns totals, then rows by rule, by refusal reason and by item. Each row counts distinct viewer keys from `access_events`: viewers who saw it locked, tried to open it, and opened it. It returns aggregates only. No viewer key, name, handle, avatar, wallet or event time leaves the server.                                                                                                                                                                                                                                                                    |
| Small buckets        | A count of 1 to 4 viewers leaves the server as `"under_5"` and shows as "Under 5". An open rate shows only when both opened and tried are 5 or more. Otherwise it shows "Not enough yet". The rule lives in `@repo/constants` (`accessStatCount`, `accessOpenRate`) and runs on the server.                                                                                                                                                                                                                                                                                                                              |
| Rules in the list    | Rules in use and saved (named) rules. The inline leaves of an Any of these or All of these rule are hidden. The combinator carries their events.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| By item              | The 20 items or blocks with the most locked views, each with its title or block label. A resource no longer on the creator's page is dropped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| People, Access tab   | `AccessView.tsx`. Tabs are Followers, Members (when the creator has a plan) and Access (delta 7). The tab is not rendered while `accessGating` is off (delta 9). It shows the pilot line "Pool rules are open to pilot creators while counsel reviews them.", a loading skeleton, "No rules yet" when the creator has no rules, and an error card with Try again. A privacy line closes the page: "Totals only. You never see who saw, tried or opened a locked item."                                                                                                                                                   |
| Early access date    | The rule picker shows "Open to everyone on" for the item's or block's own rule (delta 4, decision 8). It saves through `access.rules.update`. The earliest date is tomorrow, at UTC midnight, so the day reads the same in every timezone, and the server refuses an earlier date even when the API is called directly. Remove date clears it. When the creator picks another rule, the date carries over to the new rule. A saved rule used elsewhere shows no date row, so one item cannot change every item that uses it. The engine already opened a rule to everyone after the date (G1). `ownerAccess` now returns `opensToAllAt`. The Access tab shows "Open to everyone on Dec 1" on the rule.                                           |
| Nightly leak scan    | `services/access/nightly.ts` runs once per UTC day after 03:00 (a Redis key per day, or a per process date without Redis). It runs the same public builders the bio, the item page and the sitemap use over up to 5,000 gated blocks and 5,000 gated items, newest first. It flags a gated block that leaves unlocked or carries its URL, body or embed, a gated item with no gate or with a cover, and a gated item in the content sitemap. The report names resources only (`block:12`, `content:abc`). It is logged and saved to `site_settings` key `access_leak_scan_last`. The target is 0 (spec success metrics). |
| Event retention      | The same nightly job deletes `access_events` older than 25 months (761 days) in batches, as `docs/legal/privacy-parameters.md` lists. Until now nothing deleted them.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

## 2. Not in this PR

1. **An admin view of the leak report.** The report is in `site_settings` and the logs. An admin tile can read it later.
2. **Locked cards after the early access date.** After the date, `check` and `checkPage` allow everyone, so the bio opens the item on tap. The server rendered card still shows the lock until the page hydrates. Showing it unlocked in server HTML is a follow up for the public builders.
3. **Members and Paid in the picker.** Still Later, as in G4 and G5. That is MB-2 and content PR 10 work.
4. **A rules manager.** Saved rules are listed with their numbers, but naming, dating and deleting a saved rule from the Access tab is not built. `access.rules.update` and `delete` exist.
