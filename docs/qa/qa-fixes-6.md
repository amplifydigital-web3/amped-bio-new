## Follow-ups

- QA-025: one server helper for the rate (cache read, batch compute, cache write) used by `getPoolByAddress`, `getPoolDetailsForModal` and `getPools`. It is ready but waits for #210, which rewrites `getPools` and the cache keys in `apps/server/src/trpc/pools/fan.ts`.
- QA-025: the public pool page `apps/landingpage/src/components/pools/PoolDetailContent.tsx` still has its own `formatRate`. It is identical today. It is part of open PRs #210 and #225, so it switches to `formatNetworkRewardRate` after they merge.
- QA-025: the rate cache uses Redis when it is configured, and a per-process memory cache when it is not. If staging runs more than one API process without Redis, two requests can still hit different cached values for up to 4 hours. `utils/cache.ts` is in an open PR and was not changed here. Confirm Redis is set on staging.
- QA-033: the public site Unfollow Undo (`apps/landingpage/src/components/follow/useFollow.ts`) still re-follows with `follow.follow`. It can switch to `follow.undoUnfollow` in a later landing PR. The new `restoreToken` field is additive, so nothing breaks today.
- QA-021: Explore > Following still lists only published, not suspended creators. A fan reaches an unpublished creator's follow through the public page or the API. Showing hidden creators in the list is a product call.
