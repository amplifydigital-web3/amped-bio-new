Command line tools use the OAuth 2.0 Device Authorization Grant (RFC 8628): the user approves a short code
in the browser while the CLI polls for tokens.

## 1. Request a device code

```bash
curl -sS https://api.amped.bio/auth/device/code \
  -H "content-type: application/x-www-form-urlencoded" \
  -d client_id=YOUR_CLIENT_ID \
  -d scope="openid profile"
```

```json
{
  "device_code": "…",
  "user_code": "WDJB-MJHT",
  "verification_uri": "https://api.amped.bio/oauth/device",
  "expires_in": 1800,
  "interval": 5
}
```

## 2. Show the code to the user

Display `user_code` and send the user to `https://api.amped.bio/oauth/device`, which redirects to our hosted
approval page. The user signs in if needed, types the code and approves it.

## 3. Poll for the token

```bash
curl -sS https://api.amped.bio/auth/device/token \
  -H "content-type: application/x-www-form-urlencoded" \
  -d grant_type=urn:ietf:params:oauth:grant-type:device_code \
  -d device_code=DEVICE_CODE \
  -d client_id=YOUR_CLIENT_ID
```

While the user has not approved yet the response is `authorization_pending`; keep polling at the advertised
`interval` and respect `slow_down`. Once approved, you receive the usual access token, ID token and, with the
`offline_access` scope, a refresh token.

Public CLI clients should register with `token_endpoint_auth_method: "none"` and use PKCE where the flow
allows it.
